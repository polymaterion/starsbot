# Stars & Premium bot (оплата в TMT, ручное подтверждение, выдача через Hex)

Telegram-бот: клиент покупает **Telegram Stars** и **Premium** за манаты, платит переводом с баланса
мобильного оператора, админ подтверждает платёж кнопкой в группе, бот выдаёт товар через
[Hex Reseller API](https://hexpay.live) со своего рублёвого депозита.

## Быстрый старт

1. Создайте бота в @BotFather, создайте админ-группу, добавьте туда бота, узнайте ID группы и свой ID.
2. `cp .env.example .env` и заполните: `BOT_TOKEN`, `ADMIN_IDS`, `ADMIN_GROUP_ID`, `HEX_API_KEY`,
   `PAY_NUMBERS`, `SUPPORT_URL` (прямая ссылка на поддержку), пароль Postgres (в `POSTGRES_PASSWORD` и в `DATABASE_URL`).
3. **Каждый админ должен один раз нажать /start у бота**, иначе Telegram не даст боту писать ему в личку
   (туда приходят предупреждения о депозите и росте цены).
4. `docker compose up -d --build`. Таблицы создаются автоматически при старте.
5. В личке с ботом (под админом): `/rate 0.045`, `/markup 10`, `/balance_hex`.

Без Docker: `pip install -r requirements.txt`, Postgres, затем `python -m app.main`.

## Как это работает

```
клиент: Звезды/Premium → @username (check-recipient) → количество/период → цена в TMT
      → способ оплаты:
         • перевод: бот выдаёт номер и точную сумму (с уникальной «копейкой»), клиент шлёт скриншот
           → карточка в админ-группе [✅ Подтвердить] [❌ Отклонить]
         • с баланса бота: списание без подтверждения
      → воркер: order/create → проверка цены → проверка депозита → order/pay → опрос статуса
      → «Заказ выполнен» или возврат на баланс бота
```

- **Цена** = цена Hex (₽) × `/rate` × (1 + `/markup`%), округление вверх до копейки.
- **Уникальная сумма**: к цене добавляется «хвост» 0.01–0.49 TMT, уникальный среди открытых платежей;
  при нехватке значений берутся следующие диапазоны. При пополнении зачисляется вся переведённая сумма.
- **Один неоплаченный платёж на клиента** (заказ или пополнение). Клиент может отменить его кнопкой
  или он сам отменится через `PAYMENT_TTL_MINUTES`.
- **Отклонение**: до `MAX_PROOF_ATTEMPTS` попыток отправить скриншот, затем платёж закрывается.
  Одинаковые скриншоты (по SHA-256) не принимаются.
- **Защита от убытка**: если Hex на `create` просит больше, чем `PRICE_GUARD_PERCENT`% над проданной ценой,
  заказ уходит админу в личку с кнопками «выполнить по новой цене» / «отменить и вернуть».
- **Депозит Hex пуст**: бот не вызывает `pay` вслепую, заказ ждёт пополнения (до `HEX_WAIT_HOURS`),
  потом отмена с возвратом на баланс бота. Админам уходит предупреждение. Порог низкого депозита —
  `HEX_LOW_BALANCE_RUB`.
- **Возвраты**: `failed`/`cancelled` у Hex → клиенту на баланс бота. `delivery_in_review` — не провал,
  деньги не возвращаются, ждём финала. Вывод с баланса на номер оператора делаете вручную.

## Команды админа (в личке с ботом)

| Команда | Действие |
|---|---|
| `/rate [число]` | курс, TMT за 1 ₽ |
| `/markup [%]` | наценка |
| `/balance_hex` | депозит Hex |
| `/stats` | клиенты, заказы по статусам, выручка |
| `/orders [N]` | последние заказы |
| `/ban ID`, `/unban ID` | блокировка |
| `/credit ID сумма` | начислить TMT на баланс |

В админ-группе — только кнопки подтверждения и отклонения платежей. Нажимать могут лишь пользователи из `ADMIN_IDS`.

## Языки (русский, туркменский)

Все тексты бота (экраны, кнопки, уведомления, ошибки, админские сообщения) лежат в `locales/ru.json` и
`locales/tk.json`, а в коде строк нет.

**Первый `/start`:** пока клиент не выбрал язык, бот показывает двуязычный экран выбора (🇹🇲 / 🇷🇺), и только
после выбора открывается меню. Так же бот спросит клиентов, которые были в базе до появления выбора языка,
или чей сохранённый язык больше не существует. Отключить: `ASK_LANGUAGE_ON_START=false`.

**Смена языка:** Профиль → кнопка «🌐 Язык» (название текущего языка в кнопке не показывается) → вкладка «Язык»
со списком языков, текущий отмечен ✅. Выбор сохраняется в БД
(колонка `users.lang`) и действует везде, в том числе в уведомлениях, которые бот шлёт сам
(подтверждение оплаты, выдача, возврат). Сообщение всегда приходит на языке получателя, а не того,
кто нажал кнопку.

В `.env`:

```
BOT_LANGUAGE=tk        # язык по умолчанию для тех, кто ещё не выбрал свой: ru | tk
ASK_LANGUAGE_ON_START=true   # спрашивать язык при первом /start; false: сразу меню на языке по умолчанию
ADMIN_LANGUAGE=        # язык сообщений админам (карточки платежей, команды); пусто = как BOT_LANGUAGE
```

- Сообщения админам не зависят от выбора клиента. Карточка платежа в группе всегда на `ADMIN_LANGUAGE`.
- Править тексты можно прямо в JSON, код менять не нужно. В `docker-compose.yml` папка `locales` примонтирована,
  поэтому достаточно `docker compose restart bot`.
- В значениях `{name}`: подстановки, их нельзя менять или удалять. Ключи с префиксом `adm.`: для админов.
- Нет ключа в выбранном языке: берётся русский. При старте бот пишет в лог, чего не хватает в `tk.json`.
- **Новый язык:** скопируйте `ru.json` в `<код>.json`, переведите значения (в том числе `lang.name`, название языка
  на нём самом) и перезапустите бот: язык сам появится в списке выбора.
- База обновляется автоматически: при старте добавляется колонка `users.lang`, существующие данные не трогаются.
- Тесты проверяют, что в файлах языков одинаковые ключи и подстановки, что все ключи из кода существуют,
  и прогоняют весь путь клиента и админа на туркменском, ища любой русский текст.
- Туркменский перевод сделан без носителя языка: перед запуском стоит дать его на вычитку.

## Поведение на лишние сообщения

Бот отвечает только на команды, кнопки и ожидаемый ввод (юзернейм, количество, сумма, скриншот).
Любой другой текст игнорируется. Меню открывается по `/start`. Нажатие кнопки от старого сообщения
показывает короткое «кнопка устарела».

## Кнопка «Поддержка»

URL-кнопка в главном меню с прямой ссылкой из `SUPPORT_URL`: `https://t.me/your_support`, `@your_support`
или `tg://…`. Если переменная пуста или некорректна, кнопка скрыта (в логе при старте будет предупреждение).

## Премиум-эмодзи

ID заданы в `app/emoji.py` (25 клиентских эмодзи + 🌐 и флаги 🇷🇺 🇹🇲 для языка). Перехватчик запросов сам заменяет эмодзи в тексте на
`<tg-emoji>` и ставит иконки на кнопки (`icon_custom_emoji_id`, эмодзи из текста кнопки убирается).
Если Telegram отклонит запрос с премиум-эмодзи, он повторяется с обычными, бот не ломается.
Условие Telegram для иконок на кнопках: у владельца бота есть Telegram Premium или у бота куплены
дополнительные юзернеймы на Fragment. Отключить: `PREMIUM_EMOJI=false`.
Для ↩️ 🛠 🚨 ℹ️ (только для админов) ID не заданы, они остаются обычными. Добавить: строка в `EMOJI_IDS`.

## Тесты

```
pip install -r requirements-dev.txt
pytest                                    # SQLite в памяти
TEST_DATABASE_URL=postgresql+asyncpg://user:pass@localhost/db pytest   # реальный Postgres
```
61 тест: клиент Hex (ретраи, 429, ошибки), цены, воркер (депозит, 402, защита цены, возвраты,
таймаут), полный путь клиента и админа через настоящий Dispatcher с двойником Telegram.

## Что проверено, а что нет

- Проверено тестами: вся логика бота, БД (SQLite и PostgreSQL 16), клиент Hex против заглушки.
- **Не проверено вживую**: реальные Telegram и Hex API (у разработчика не было токена и ключа).
  Клиент написан по брифу Hex (адреса, поля, коды ошибок сверены). Первый боевой тест:
  `/balance_hex`, затем заказ минимального количества звёзд себе.

## Известные ограничения

- Схема БД создаётся `create_all`, миграций нет. При изменении моделей нужен Alembic.
- Состояния диалога (ввод юзернейма и т.п.) хранятся в памяти: после перезапуска клиенту покажется
  «сессия устарела» и меню. Заказы и платежи при этом не теряются, они в БД.
- Платёж в статусе «на проверке» сам не отменяется (деньги клиент уже отправил). Если админы молчат,
  он будет висеть до их решения.
- Один экземпляр бота (воркер без блокировок между процессами).
- Имя получателя (как в оригинальных скриншотах) показать нельзя: Hex отдаёт только `valid`.
